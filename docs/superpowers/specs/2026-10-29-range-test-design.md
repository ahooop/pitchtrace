# 音迹 PitchTrace · 音域测试设计说明

日期：2026-10-29
状态：设计已确认，实施中

## 1. 背景

练习模式回答「这一句唱得准不准」，但不回答「我能唱到多高多低」。
音域测试要给出两个稳定极值：能持续唱出来的最低音和最高音。

难点不在检测音高（现有 YIN 管道已经够用），而在**什么才算数**：

- 瞬时极值不可信，咳嗽、椅子响、换气都能刷出记录；
- 手机麦克风低频响应差，C2（65Hz）以下明显衰减，测出来的「最低」可能是麦克风的底。

所以结果是「稳定唱到」的极值，并且对低音侧给出可信度提示。

## 2. 两种采集器

| 采集器 | 场景 | 输入 | 输出 |
|---|---|---|---|
| `RangeProbe` | 自由唱 | 实时 `PitchSample` 流 | 稳定极值 + 各自保持时长 |
| `GuidedSweep` | 引导扫频 | 完整样本列表 + 扫频定义 | 两个方向各自到达的极限 |

四种入口都由这两者组合：

1. 引导测：只跑 `GuidedSweep`；
2. 自由测：只跑 `RangeProbe`；
3. 混合：先自由热身，再自动接引导确认；
4. 最简：自由测 + 手动结束（与 2 同一实现，只是不引导）。

## 3. 结果模型

```kotlin
enum class RangeSource { FREE, GUIDED, MIXED }

data class RangeResult(
    val lowMidi: Float,
    val highMidi: Float,
    val lowStableMs: Long = 0L,
    val highStableMs: Long = 0L,
    val source: RangeSource = RangeSource.FREE,
)
```

派生属性：

- `hasRange`：两个极值都有效且 high ≥ low；
- `spanSemitones`：跨度；
- `lowLimitedByMic`：`lowMidi ≤ C2`（36.5），提示可能受麦克风限制；
- `recommendedRange()`：选能容纳 `[low-1, high+1]` 的最小档位，否则 `FULL`。

混合模式用 `RangeResult.merge(free, guided)`：低音取更低的、高音取更高的。

## 4. 稳定判定（RangeProbe）

维护一个「当前音高段」：

1. 新样本与段内中位数偏差 ≤ 1 半音 → 延续；
2. 偏差超过 1 半音，或与上一帧间隔 > 250ms → 结束当前段并结算，然后以新样本开新段；
3. 段时长 ≥ 300ms 且样本数 ≥ 3 才提交：取段内中位数，更新最低/最高；
4. 用户手动结束或测试超时调用 `finish()`，把最后一段也结算。

这样抖动、滑音、短促噪声都不会成为记录。

## 5. 引导扫频（GuidedSweep）

### 5.1 扫频定义

`RangeExercise.sweep(center = 60, down = 24, up = 24)`：

- 音符序列：C4 → B3 → … → C2（向下 24 个半音），再从 C#4 → … → C6（向上 24 个半音）；
- 每音 700ms，间隙 100ms；
- 总时长约 39 秒，共 49 个音。

`RangeSweep` 记录 `centerMidi`、`downCount`、`upCount`，并给出两段的索引区间。

### 5.2 判定

1. 时间偏移搜索：`offset ∈ [-400ms, +400ms]`，步长 40ms，取「命中音数最多」的偏移（抵消播放/采集延迟）；
2. 单个音命中：窗口 `[start+offset, end+offset]` 内样本数达到窗口栅格的 25%，且中位数与目标音高差 ≤ **0.5 个半音**；
   扫频是逐半音进行的，容差放到 1 个半音就会让每个音都匹配到邻居，永远触发不了「跟不上」；
3. 方向行走：从起点出发，命中则记录并清零失败计数；连续 2 个音未命中即停，该方向结束；
4. 向下段取最小命中音高为 `lowMidi`，向上段取最大为 `highMidi`。

### 5.3 逐音标记（不打断播放）

扫频进行中，每播完一个音就判定一次，结果标在底部进度条上：

- 绿 = 这个音唱对了；
- 红 = 没唱对/没唱；
- 灰 = 还没轮到。

判定窗口尾部多留 250ms，兜住「人总比参考音慢一点」的跟唱延迟。

**播放不会因为跟不上而中断**：用户可以一直跟到极限，自己点「结束」收工；
只有整段扫频自然播完时才自动收尾。标记只是给人看的参考，不改变播放行为。

## 6. 界面

主界面模式切换变为三档：`自由聆听 / 练习 / 音域`。

音域页：

- 实时大字：「最低 C2 · 最高 A4」，未测到时显示「—」；
- 卷帘上画两条水平标记线，标出当前极值；
- 两个按钮：`自由测`、`引导测`；
- 自由测结束提示「接着用引导确认极限？」；
- 结果卡片：最低音 + 频率、最高音 + 频率、跨度（半音数与度数）、推荐档位、`用这个档位显示`。

## 7. 错误处理

| 情况 | 处理 |
|---|---|
| 全程没有稳定音 | 结果页显示「没有检测到稳定的音」，不保存 |
| 最低音 ≤ C2 | 结果卡片提示「低音可能受手机麦克风限制」 |
| 未授权麦克风 | 沿用现有权限流程 |
| 引导中途停止 | 用已唱部分评分，未到达的方向显示「—」 |
| 页面退到后台 | 停止采集与播放，丢弃未完成结果 |

## 9. 取舍与风险

| 风险 | 对策 |
|---|---|
| 低音测不准 | 结果标注 `lowLimitedByMic`，文案说明是麦克风限制，不当作真实音域 |
| 用户不会往极限唱 | 引导扫频逐半音提示，跟着唱即可 |
| 假声/哨音算不算 | 算——「能稳定发出」就是音域，不做声区区分 |
| 扫频耗时 39 秒 | 连续失败自动停；也允许中途手动结束 |
| 评价标准主观 | 只报极值与跨度，不打分、不与他人比较 |
